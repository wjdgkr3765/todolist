# overview.md

프로젝트 개요의 기준 문서다. 설계와 각 단계의 완료 기준은 이 문서를 기준으로 정한다.

기능이나 범위를 바꾸는 작업에서는 이 문서도 함께 갱신한다. 사용자 승인 없이 기능과 범위를 바꾸지 않는다.

비어 있는 항목이 있으면 loop.md 1번(설계)에서 사용자에게 질문해서 채운다.

## 1. 기본 정보

## 8. 기능별 요구사항

상세 설계(DB, API, 화면)는 database.md, api.md, 각 `{화면파일명}_screen.md` 에 있다. 이 장은 기능별로 정해진 규칙을 모은 것이다.

### 8.1 회원 입력 규칙 (D-006, D-026, D-036, D-037)
| 항목 | 규칙 | 중복 |
|---|---|---|
| 아이디 | 영어와 숫자를 둘 다 포함, 6~15자 | 불가 |
| 비밀번호 | 영어 + 숫자 + 특수문자를 모두 포함, 8~15자 | |
| 닉네임 | 한글, 영어, 숫자만, 1~8자 | 허용 |
| 이메일 | 정규식 `` ^[A-Za-z0-9.!#$%&'*+/=?^_`{|}~-]+@[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?(?:\.[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?)+$ ``, 최대 100자 | 불가 |
| 전화번호 | 숫자만, 하이픈 없이 11자리 (시작 번호 제한 없음) | 불가 |

- 이전 프로젝트에서 AI가 해석해 사용자에게 알렸고 이의가 없었던 것: 비밀번호의 특수문자는 공백 없는 ASCII 특수문자, 닉네임의 한글은 완성형만

### 8.2 회원가입
- 중복 확인 (D-038, D-042): 아이디만 [중복 확인] 버튼. 이메일은 [인증번호 발송]을 누르면 먼저 중복을 확인하고 중복이 아니면 인증번호를 보낸다. 전화번호는 [가입하기]를 누를 때 서버에서 확인하고 중복이면 전화번호 칸에 오류
- 이메일 인증번호 (D-035): 6자리 숫자, 유효시간 5분, 재발송은 1분 뒤부터, 5번 틀리면 그 번호는 무효
- 재발송하면 이전 인증번호는 무효 (같은 이메일·용도의 이전 기록을 지움, D-045)
- 인증을 마친 뒤 이메일을 고치면 인증을 취소하고 다시 인증 (D-039)
- 인증 완료 시각부터 30분 안에 가입해야 한다. 지나면 다시 인증 (D-044)
- 비밀번호는 bcrypt 해시로 저장
- 가입에 성공하면 모든 입력칸과 버튼을 잠그고(D-048) "가입이 완료되었습니다" 안내 후 로그인 화면으로 이동 (D-040)
- 인증 메일 (D-046, D-047): 보낸 사람 이름 "TODO"(주소는 환경 변수 MAIL_USER), 제목 "[TODO] 회원가입 인증번호". 간단한 HTML 본문(기본색 #1FAA59 제목, 큰 글씨 6자리 번호, "5분 안에 입력해 주세요. 본인이 요청하지 않았다면 이 메일을 무시해 주세요.")과 같은 내용의 텍스트 본문을 함께 보낸다

### 8.3 로그인/로그아웃
- 브라우저를 닫았다 열어도 로그인 후 24시간 유지 (D-007)
- 로그인 토큰을 DB에 저장(해시)하고 httpOnly + SameSite 쿠키로 주고받는다. 로그아웃 시 DB에서 무효화 (D-028)
- 아이디별로 비밀번호를 연속 5번 틀리면 10분 동안 그 아이디의 로그인을 막는다. 성공하면 틀린 횟수 초기화 (D-049)
- 한 곳에서만 로그인. 새로 로그인하면 그 회원의 다른 로그인은 무효 (D-050)
- 로그인 확인용 API(GET /api/sessions/me)로 화면 이동을 막는다 (D-051)
- 비회원 로그인 확인(401), 로그인 실패(401) 같은 계획된 API 오류 응답 때문에 Chrome 콘솔에 찍히는 "Failed to load resource" 는 정상으로 본다. 코드에서 난 오류만 문제로 본다 (D-052)

### 8.4 공통 레이아웃
- 화면 좌측 상단 "TODO" 오른쪽에 알림 종 아이콘, 누르면 알림 목록 (D-009)
- 로그아웃은 좌측 하단 닉네임·이메일 영역을 누르면 열리는 작은 메뉴 안에 둔다. 회원정보 수정 항목도 이 메뉴에 추가한다 (D-053)
- 반응형: 모바일에서도 서랍(offcanvas)으로 바꾸지 않고 같은 배치를 그대로 줄인다. 영역마다 최소 크기를 두고 그보다 좁으면 가로 스크롤 (D-054, 수치는 MainLayout_screen.md)
- 팀 만들기: 좌측 네비 "팀" 제목 오른쪽 [+] 버튼 → 가운데 모달에서 팀 이름 입력. 만들면 그 팀의 팀 정보 탭으로 이동 (D-073)
- 개인 공간에는 팀 정보 탭과 작업자 지정이 없다 (D-074)

### 8.5 작업 페이지 - 할일 목록
- 할일 항목: 제목, 내용, 기간(시작일~종료일) 모두 필수. 기간을 정하지 않으려면 "미정" 선택. 목록에는 제목과 기간 표시 (D-010)
- 제목 최대 50자(목록에서 넘치면 …), 내용 최대 2000자 (D-058)
- [작업 시작] 버튼(D-018)은 [추가]/[삭제]/[수정] 버튼과 같은 줄 (D-011)
- 추가/수정 UI는 오른쪽 "작업 수정 UI" 영역에 띄우고, X를 누르면 사라지며 작업 공간이 반응형으로 넓어진다. 작업 공간에는 min-width, min-height 지정 (D-011)
- 행 하나를 클릭해 선택(행 강조)하고, 버튼은 선택한 하나에 대해 동작 (D-055)
- 삭제는 확인창 후 DB에서 완전 삭제 (D-056)
- 정렬은 최근 추가 순 (새 할일이 맨 위, D-057)
- [작업 시작]을 누르면 할일 목록에서 빼고 칸반 작업으로 옮긴다 (할일 삭제 + 작업 생성을 한 번에, D-059). 대기 공간 맨 위에 둔다 (D-064)

### 8.6 작업 페이지 - 칸반보드
- 상세 UI 항목: 제목, 작업 내용, 기간, 상태(드롭다운), 작업자(드롭다운, 여러 명), 수정 내역 목록, 수정 버튼 (D-012). 작업자는 팀 작업 페이지에서 만든다 (D-060)
- 상세 UI 위치는 오른쪽 영역 (할일 입력 UI와 같은 자리, D-061)
- 처음엔 읽기 보기, [수정]을 누르면 같은 자리에서 입력칸으로 바뀐다. 상태 드롭다운도 수정할 때 바꾼다. [삭제]도 상세 UI에 둔다 (D-062)
- 칸반 카드에는 제목 + 기간 (D-063)
- 작업 삭제는 확인창 후 완전 삭제 (D-023)
- 수정 내역 (D-013, D-065, D-067, D-068, D-070)
  - 작업 생성, 작업 수정, 상태 변경(상세 UI 수정·드래그 모두)마다 한 줄씩 남긴다. 같은 공간 안 순서 변경은 남기지 않는다
  - 한 줄: 시각, 그 시점 닉네임, 종류("작업 생성" / "작업 수정" / "상태 변경 (대기 → 진행)")
  - 내용과 상태를 한 번에 바꿔 저장하면 한 줄로 "작업 수정 · 상태 변경 (대기 → 진행)"
  - 바뀐 것 없이 저장하면 수정 내역을 남기지 않고 마지막 수정 시각도 바꾸지 않는다
  - 한 줄을 누르면 그 시점의 작업 전체(제목, 내용, 기간, 상태)를 모달로 보여준다 (기록마다 그 시점 작업 내용 저장)
  - 목록은 최근 것이 위 (작업 생성이 맨 아래)
- 상태가 바뀐 작업의 위치 (D-069): 드래그는 놓은 자리. 상세 UI 상태 드롭다운으로 바꿔 저장하면 옮겨 간 공간의 맨 위
- 완료 시각 (D-015, D-066): 완료 공간으로 옮긴 시각을 기록. 완료에서 빠지면 지우고, 다시 완료로 옮긴 시각부터 일주일을 센다

### 8.7 팀 생성/관리 (팀 정보 탭) — 결정만 있음, DB·API·화면 설계 전
- 팀 정보는 팀 이름만. 1~20자. 다른 팀과 이름이 같아도 된다 (팀은 id로 구분, D-071)
- 역할과 상관없이 가입된 팀 수를 센다. 가입된 팀이 20개면 새 팀을 만들 수 없고, 초대를 받아 가입하는 것도 20개를 넘을 수 없다. 한 팀의 팀원 수는 제한 없음 (D-078)
- 만든 회원이 관리자(owner). 좌측 네비에 내가 속한 팀 목록, 누르면 그 팀 공간(/teams/{팀 id}/...)으로 이동
- 팀 정보 탭 (D-074, D-079, D-081) — 위에서 아래로
  1. 팀 정보 카드: 팀 이름, 관리자 닉네임, 팀원 수, 만든 날짜. 관리자·부관리자에게 [이름 수정] → 같은 자리에서 수정
  2. 팀원 게시판: 팀원 목록 표다(글 쓰는 게시판 아님). 닉네임, 이메일, 역할 배지, 합류일. 관리자 → 부관리자 → 팀원 순, 같은 역할은 먼저 합류한 순 (D-076). 행 오른쪽 [⋮] 메뉴: 부관리자 지정·해제, 관리자 넘기기(확인창), 내보내기(확인창). 내 권한으로 할 수 있는 것만 보이고, 없으면 [⋮] 숨김
  3. 맨 아래 폭 100% 버튼: 관리자는 빨간 [팀 해체] / 부관리자·팀원은 빨간 테두리 [팀 탈퇴] + 확인창
- 팀 해체 (D-075, D-080): 확인창에 팀 이름을 보여주고 입력칸을 둔다. 팀 이름과 똑같이(앞뒤 공백만 무시) 입력해야 [다음]이 켜진다 → "정말 삭제할까요? 되돌릴 수 없습니다." 확인창 → [삭제]로 해체. 서버도 팀 이름을 받아 다시 확인한다. 그 팀과 관련된 정보를 완전히 지운다
- 관리자를 넘기면 원래 관리자는 부관리자가 된다 (D-077)
- 관리자는 관리자를 넘긴 뒤에만 탈퇴. 혼자 남은 팀은 팀 해체가 곧 탈퇴 (D-019)
- 팀 공간의 작업·캘린더·히스토리 탭은 팀 작업 페이지 등 해당 작업에서 만든다 (D-072)
- 팀 만들기 모달은 공통 레이아웃에 둔다 (D-073)
- 이전 프로젝트에서 승인된 진행 계획 (참고)
  - DB: teams(팀 정보), team_members(팀·회원·역할 owner/manager/member·합류 시각, 팀·회원 조합 UNIQUE, 팀 해체 시 함께 삭제)
  - API: 내 팀 목록, 팀 만들기, 팀 정보(내 역할 포함), 팀원 목록, 팀 정보 수정, 팀원 내보내기, 역할 변경(부관리자 지정·해제), 관리자 넘기기, 팀 탈퇴, 팀 해체. 권한·소속 확인은 서버에서, 역할을 바꾸는 처리는 트랜잭션
  - 팀에 속하지 않은 회원은 팀 정보·팀원 목록을 보거나 바꿀 수 없다 (404). 권한이 없는 요청은 서버에서 막는다
  - 테스트: 역할별 권한 표, 경계값, 남의 팀, 관리자 혼자 탈퇴, 동시 변경
  - 화면: MainLayout 갱신(팀 목록·팀 만들기·팀 공간 메뉴 탭), TeamInfoView 새로 작성

### 8.8 팀 초대/알림
- 초대와 팀 탈퇴는 팀원 누구나 가능 (D-008)
- 이메일로 회원을 지정해 초대 → 알림 생성 + 안내 메일. 초대 메일은 안내만 하고, 수락/거절은 사이트 알림에서 한다 (D-009)
- 알림 종류는 지금은 팀 초대만. 다른 알림은 나중에 필요하면 추가 (D-024)
- 초대 수락으로 가입된 팀이 20개를 넘을 수 없다 (D-078)

### 8.9 팀 작업 페이지
- 팀 공간의 할일·칸반·작업자 지정 (D-060, D-072). 작업자는 여러 명 (D-012)
- 할일·작업 테이블에 팀 공간(team_id)을 이 작업에서 추가한다

### 8.10 실시간 반영
- 작업 페이지의 생성/수정/삭제/이동을 같은 팀 접속자 화면에 실시간 반영 (Socket.IO)

### 8.11 캘린더
- 라이브러리 사용 (FullCalendar, D-002)
- 작업을 기간에 맞춰 가로 막대로 표시하고 상태별로 색을 다르게 한다. 칸반에 올라가지 않은 할일은 표시하지 않는다 (D-014)
- 히스토리로 옮긴 작업도 계속 표시한다 (D-015)
- 기간이 "미정"인 작업은 표시하지 않는다 (D-022)
- 보기 전용, 클릭 시 상세 모달, 오늘 날짜에 원 표시
- 참고자료: docs/reference/캘린더 참고.png

### 8.12 히스토리
- 완료 공간으로 옮긴 시각부터 일주일이 지나면 히스토리로 옮긴다 (D-015). 완료에서 빠졌다가 다시 완료되면 그 시각부터 센다 (D-066)
- 테이블로 표시, 클릭 시 상세 모달, 읽기 전용

### 8.13 아이디/비밀번호 찾기 (D-020)
- 이메일 인증번호로 본인을 확인한다 (인증번호 규칙은 회원가입과 같음)
- 아이디는 화면에 보여준다. 비밀번호는 새 비밀번호를 입력받아 재설정한다

### 8.14 회원정보 수정/탈퇴
- 아이디는 변경 불가. 이메일은 바꿀 때 다시 인증. 전화번호는 인증 없이 변경 (D-021)
- 탈퇴 (D-041): 회원 정보(아이디, 이메일, 전화번호 등)를 하드 삭제해 같은 값으로 다시 가입할 수 있게 한다. 개인 공간의 작업도 삭제한다. 팀 작업과 수정 내역은 남기고 저장해 둔 그 시점의 닉네임으로 계속 표시한다. 작업자 지정에서는 그 회원만 빠진다. 재가입한 회원과 예전 기록은 연결하지 않는다
- 공통 레이아웃의 회원 메뉴(닉네임·이메일 클릭)에 회원정보 수정 항목을 추가한다 (D-053)

### 공통 화면 규칙
- 알림(토스트)은 화면 위쪽 가운데 카드. 안내·성공은 초록 띠, 오류는 빨강 띠
- 서버 오류 토스트 문구: "일시적인 오류가 발생했습니다. / 잠시 후 다시 시도해 주세요."
- 로딩 중인 버튼은 안에 작은 스피너 + "~ 중..." 문구, 비활성
- 입력 오류: 입력칸 빨강 테두리 + 칸 아래 빨강 문구(느낌표 아이콘)
- 입력 중(포커스): 흰 배경 + 기본색 테두리 + 연한 녹색 바깥 빛, 왼쪽 아이콘 기본색
- 공통 디자인 값은 한 파일에 모아 모든 화면이 같이 쓴다 (이전 프로젝트에서는 assets/styles/theme.css)
