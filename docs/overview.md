# overview.md

프로젝트 개요의 기준 문서다. 설계와 각 단계의 완료 기준은 이 문서를 기준으로 정한다.

기능이나 범위를 바꾸는 작업에서는 이 문서도 함께 갱신한다. 사용자 승인 없이 기능과 범위를 바꾸지 않는다.

비어 있는 항목이 있으면 loop.md 1번(설계)에서 사용자에게 질문해서 채운다.

---

## 1. 기본 정보

- **프로젝트 이름**: 일정관리 협업 시스템 (D-001)
- **한 줄 소개**: 개인과 팀이 칸반보드와 캘린더로 할 일을 함께 관리하는 웹 서비스
- **목적**: 팀원끼리 작업의 상태(대기/진행/완료)와 작업자를 실시간으로 공유하고, 일정을 캘린더로 확인하며, 끝난 작업을 히스토리로 남긴다
- **화면 로고 이름**: TODO

## 2. 사용자와 권한

| 사용자 | 설명 | 할 수 있는 일 |
|---|---|---|
| 비회원 | 로그인하지 않은 사용자 | 회원가입(이메일 인증), 로그인, 아이디 찾기, 비밀번호 찾기 (이메일 인증) |
| 회원 | 로그인한 사용자 | 개인 공간 사용(작업, 캘린더, 히스토리), 팀 생성, 알림 확인(팀 초대·작업자 지정·마감 임박), 초대 수락/거절, 회원정보 수정(닉네임·이메일·전화번호·비밀번호), 회원 탈퇴 |
| 팀원 | 팀에 속한 회원 (역할: member) | 팀 공간 사용(작업 페이지 할일·칸반 생성/수정/삭제, 캘린더·팀 정보·히스토리 보기, 일일보고 쓰기·보기), 다른 회원 초대, 팀 탈퇴 |
| 부관리자 | 관리자가 역할을 부여한 팀원, 여러 명 가능 (역할: manager) | 팀원의 모든 권한 + 팀 정보 수정, 일반 팀원 내보내기 (부관리자·관리자는 내보낼 수 없음) |
| 팀 관리자 | 팀을 만든 회원, 팀마다 1명 (역할: owner) | 부관리자의 모든 권한 + 부관리자 내보내기, 팀 해체, 역할 부여(부관리자 지정·해제), 관리자 넘기기(부관리자·팀원 누구에게나). 다른 팀원에게 관리자를 넘겨야만 탈퇴 가능, 혼자 남은 팀이면 탈퇴 시 팀 해체 |

(D-008, D-019, D-030)

## 4. 범위

### 포함
- 위 "핵심 기능"의 모든 기능
- PC 화면을 기본으로 하고 모바일 화면(반응형)도 지원 (D-003)

### 제외

- 실제 서버 배포 (서버, 도메인, HTTPS, 운영 메일 계정). 이번 프로젝트는 로컬 실행까지 (D-124)

- Vue 파일명은 PascalCase, 화면 설계 문서는 같은 폴더에 `{화면파일명}_screen.md` (D-025)
- 팀 공간 경로는 `/teams/{팀 id}/tasks`(작업), `/teams/{팀 id}/calendar`(캘린더), `/teams/{팀 id}/info`(팀 정보), `/teams/{팀 id}/history`(히스토리), `/teams/{팀 id}/reports`(일일보고, D-151). 작업·캘린더·히스토리 탭은 개인 공간과 같은 화면 파일을 쓴다

### 화면 흐름
- 로그인 → 개인 작업 화면(/personal/tasks, 기본). `/` 는 /personal/tasks 로 보낸다
- 로그인 → 회원가입 / 아이디 찾기 / 비밀번호 찾기 → 로그인
- 좌측 네비에서 개인 또는 팀 선택 → 메뉴 탭 선택
  - 개인 공간: 작업 / 캘린더 / 히스토리
  - 팀 공간: 작업 / 캘린더 / 팀 정보 / 히스토리 / 일일보고 (D-074, D-151). 좌측 네비에서 팀을 누르면 그 팀의 작업 탭
- 팀 만들기 모달 → 만든 팀의 팀 정보 탭 (D-073)
- 팀 정보 탭에서 팀 탈퇴·팀 해체 → 개인 작업 화면(/personal/tasks)
- 로그인 여부에 따라 자동으로 돌려보낸다: 로그인한 회원이 로그인·회원가입 화면에 오면 로그인 후 화면으로, 비회원이 회원 전용 화면에 오면 로그인 화면으로 (D-051)
- 좌측 하단 회원 메뉴 → 회원정보 수정(/profile). 탈퇴하면 로그인 화면
- 알림(작업자 지정·마감 임박)을 누르면 그 작업 화면으로 가서 상세를 연다
- 없는 주소는 로그인했으면 /personal/tasks, 아니면 /login (D-119)

## 7. 제약 사항

- **지원 브라우저**: Chrome 최신 버전 (PC 기본, 모바일 반응형 지원)
- **메일 발송**: Gmail SMTP (D-004). 접속 정보는 환경 변수
- **공휴일 정보**: 공공데이터포털 "한국천문연구원 특일 정보" API (D-107). 키는 환경 변수 HOLIDAY_API_KEY
- **DB**: SQL Server 2019
- **Node.js**: 24 LTS (D-017)

## 8. 기능별 요구사항

상세 설계(DB, API, 화면)는 database.md, api.md, 각 `{화면파일명}_screen.md` 에 있다. 이 장은 기능별로 정해진 규칙을 모은 것이다.

### 8.1 회원 입력 규칙 (D-006, D-026, D-036, D-037)
| 항목 | 규칙 | 중복 |
|---|---|---|
| 아이디 | 영어와 숫자를 둘 다 포함, 6~15자 | 불가 |
| 비밀번호 | 영어 + 숫자 + 특수문자를 모두 포함, 8~15자 | |
| 닉네임 | 한글, 영어, 숫자만, 1~8자 | 허용 |
| 이메일 | 정규식 `` ^[A-Za-z0-9.!#$%&'*+/=?^_`{|}~-]+@[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?(?:\.[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?)+$ ``, 최대 100자 | 불가 |
| 전화번호 | 숫자만, 하이픈 없이 11자리 (시작 번호 제한 없음) | 불가 |

- 이전 프로젝트에서 AI가 해석해 사용자에게 알렸고 이의가 없었던 것: 비밀번호의 특수문자는 공백 없는 ASCII 특수문자, 닉네임의 한글은 완성형만

### 8.2 회원가입
- 중복 확인 (D-038, D-042): 아이디만 [중복 확인] 버튼. 이메일은 [인증번호 발송]을 누르면 먼저 중복을 확인하고 중복이 아니면 인증번호를 보낸다. 전화번호는 [가입하기]를 누를 때 서버에서 확인하고 중복이면 전화번호 칸에 오류
- 이메일 인증번호 (D-035): 6자리 숫자, 유효시간 5분, 재발송은 1분 뒤부터, 5번 틀리면 그 번호는 무효
- 재발송하면 이전 인증번호는 무효 (같은 이메일·용도의 이전 기록을 지움, D-045)
- 인증을 마친 뒤 이메일을 고치면 인증을 취소하고 다시 인증 (D-039)
- 인증 완료 시각부터 30분 안에 가입해야 한다. 지나면 다시 인증 (D-044)
- 비밀번호는 bcrypt 해시로 저장
- 가입에 성공하면 모든 입력칸과 버튼을 잠그고(D-048) "가입이 완료되었습니다" 안내 후 로그인 화면으로 이동 (D-040)
- 인증 메일 (D-046, D-047): 보낸 사람 이름 "TODO"(주소는 환경 변수 MAIL_USER), 제목 "[TODO] 회원가입 인증번호". 간단한 HTML 본문(기본색 #1FAA59 제목, 큰 글씨 6자리 번호, "5분 안에 입력해 주세요. 본인이 요청하지 않았다면 이 메일을 무시해 주세요.")과 같은 내용의 텍스트 본문을 함께 보낸다

### 8.3 로그인/로그아웃
- 브라우저를 닫았다 열어도 로그인 후 24시간 유지 (D-007)
- 로그인 토큰을 DB에 저장(해시)하고 httpOnly + SameSite 쿠키로 주고받는다. 로그아웃 시 DB에서 무효화 (D-028)
- 아이디별로 비밀번호를 연속 5번 틀리면 10분 동안 그 아이디의 로그인을 막는다. 성공하면 틀린 횟수 초기화 (D-049)
- 한 곳에서만 로그인. 새로 로그인하면 그 회원의 다른 로그인은 무효 (D-050)
- 로그인 확인용 API(GET /api/sessions/me)로 화면 이동을 막는다 (D-051)
- 비회원 로그인 확인(401), 로그인 실패(401) 같은 계획된 API 오류 응답 때문에 Chrome 콘솔에 찍히는 "Failed to load resource" 는 정상으로 본다. 코드에서 난 오류만 문제로 본다 (D-052)

### 8.4 공통 레이아웃
- 화면 좌측 상단 "TODO" 오른쪽에 알림 종 아이콘, 누르면 알림 목록 (D-009)
- 로그아웃은 좌측 하단 닉네임·이메일 영역을 누르면 열리는 작은 메뉴 안에 둔다. 회원정보 수정 항목도 이 메뉴에 추가한다 (D-053)
- 반응형: 모바일에서도 서랍(offcanvas)으로 바꾸지 않고 같은 배치를 그대로 줄인다. 영역마다 최소 크기를 두고 그보다 좁으면 가로 스크롤 (D-054, 수치는 MainLayout_screen.md)
- 팀 만들기: 좌측 네비 "팀" 제목 오른쪽 [+] 버튼 → 가운데 모달에서 팀 이름 입력. 만들면 그 팀의 팀 정보 탭으로 이동 (D-073)
- 개인 공간에는 팀 정보 탭과 작업자 지정이 없다 (D-074)

### 8.5 작업 페이지 - 할일 목록
- 할일 항목: 제목, 내용, 기간(시작일~종료일) 모두 필수. 기간을 정하지 않으려면 "미정" 선택. 목록에는 제목과 기간 표시 (D-010)
- 기간 시간 (D-135, D-136, D-139): "시간 지정"을 켜면 시작·종료 시간을 함께 넣는다 (켤 때 09:00, 18:00 을 미리 채움). 5분 단위. 끄면 날짜만. 입력한 한국 시간 그대로 저장
  - 표시: `2026.11.10 09:00 ~ 2026.11.20 18:00`, 같은 날이면 `2026.11.12 09:00 ~ 18:00`. 칸반 카드·할일 목록에는 `~ 2026.11.20 18:00` 처럼 종료일만 보여주고, 마우스를 올리면 시작~종료 전체를 보여준다 (D-142). 넘치면 …로 줄인다
- 제목 최대 50자(목록에서 넘치면 …), 내용 최대 2000자 (D-058)
- [작업 시작] 버튼(D-018)은 [추가]/[삭제]/[수정] 버튼과 같은 줄 (D-011)
- 추가/수정 UI는 오른쪽 "작업 수정 UI" 영역에 띄우고, X를 누르면 사라지며 작업 공간이 반응형으로 넓어진다. 작업 공간에는 min-width, min-height 지정 (D-011)
- 행 하나를 클릭해 선택(행 강조)하고, 버튼은 선택한 하나에 대해 동작 (D-055)
- 삭제는 확인창 후 DB에서 완전 삭제 (D-056)
- 정렬은 최근 추가 순 (새 할일이 맨 위, D-057)
- [작업 시작]을 누르면 할일 목록에서 빼고 칸반 작업으로 옮긴다 (할일 삭제 + 작업 생성을 한 번에, D-059). 대기 공간 맨 위에 둔다 (D-064)

### 8.6 작업 페이지 - 칸반보드
- 상세 UI 항목: 제목, 작업 내용, 기간, 상태(드롭다운), 작업자(드롭다운, 여러 명), 수정 내역 목록, 수정 버튼 (D-012). 작업자는 팀 작업 페이지에서 만든다 (D-060)
- 상세 UI 위치는 오른쪽 영역 (할일 입력 UI와 같은 자리, D-061)
- 처음엔 읽기 보기, [수정]을 누르면 같은 자리에서 입력칸으로 바뀐다. 상태 드롭다운도 수정할 때 바꾼다. [삭제]도 상세 UI에 둔다 (D-062)
- 칸반 카드에는 제목 + 기간 (D-063). 기간은 "~ 종료일"만, 전체 기간은 상세 UI 에서 (D-142). 팀 공간 카드에는 작업자도 (1명이면 닉네임, 2명 이상이면 "첫 닉네임 외 N명", D-098)
- 기한이 지났는데 대기·진행인 작업은 카드와 상세 UI 에 빨간 기간 + "기한 지남" 배지 (D-125). 시간이 있으면 종료 시각이 지나면 바로, 시간이 없으면 종료일이 오늘보다 앞일 때 (D-137)
- 작업 삭제는 확인창 후 완전 삭제 (D-023)
- 수정 내역 (D-013, D-065, D-067, D-068, D-070)
  - 작업 생성, 작업 수정, 작업자 변경(팀 공간, D-099), 상태 변경(상세 UI 수정·드래그 모두)마다 한 줄씩 남긴다. 같은 공간 안 순서 변경은 남기지 않는다
  - 한 줄: 시각, 그 시점 닉네임, 종류("작업 생성" / "작업 수정" / "작업자 변경" / "상태 변경 (대기 → 진행)")
  - 여러 가지를 한 번에 바꿔 저장하면 한 줄로 "작업 수정 · 작업자 변경 · 상태 변경 (대기 → 진행)" (바뀐 것만, D-067, D-100)
  - 바뀐 것 없이 저장하면 수정 내역을 남기지 않고 마지막 수정 시각도 바꾸지 않는다
  - 한 줄을 누르면 그 시점의 작업 전체(제목, 내용, 기간, 상태, 팀 공간이면 작업자)를 모달로 보여준다 (기록마다 그 시점 작업 내용 저장)
  - 목록은 최근 것이 위 (작업 생성이 맨 아래)
- 상태가 바뀐 작업의 위치 (D-069): 드래그는 놓은 자리. 상세 UI 상태 드롭다운으로 바꿔 저장하면 옮겨 간 공간의 맨 위
- 완료 시각 (D-015, D-066): 완료 공간으로 옮긴 시각을 기록. 완료에서 빠지면 지우고, 다시 완료로 옮긴 시각부터 일주일을 센다

### 8.7 팀 생성/관리 (팀 정보 탭)
- 팀 정보는 팀 이름만. 1~20자. 다른 팀과 이름이 같아도 된다 (팀은 id로 구분, D-071)
- 역할과 상관없이 가입된 팀 수를 센다. 가입된 팀이 20개면 새 팀을 만들 수 없고, 초대를 받아 가입하는 것도 20개를 넘을 수 없다. 한 팀의 팀원 수는 제한 없음 (D-078)
- 만든 회원이 관리자(owner). 좌측 네비에 내가 속한 팀 목록, 누르면 그 팀의 작업 탭(/teams/{팀 id}/tasks)으로 이동 (D-090)
- 팀 목록은 나중에 합류한(만든) 팀이 위. 드래그로 순서를 바꿀 수 있고 회원마다 저장된다 (D-089)
- 팀 정보 탭 (D-074, D-079, D-081) — 위에서 아래로
  1. 팀 정보 카드: 팀 이름, 관리자 닉네임, 팀원 수, 만든 날짜. 관리자·부관리자에게 [이름 수정] → 같은 자리에서 수정
  2. 팀원 게시판: 팀원 목록 표다(글 쓰는 게시판 아님). 닉네임, 이메일, 역할 배지, 합류일. 관리자 → 부관리자 → 팀원 순, 같은 역할은 먼저 합류한 순 (D-076). 행 오른쪽 [⋮] 메뉴: 부관리자 지정·해제, 관리자 넘기기(확인창), 내보내기(확인창). 내 권한으로 할 수 있는 것만 보이고, 없으면 [⋮] 숨김
  3. 맨 아래 폭 100% 버튼: 관리자는 빨간 [팀 해체] / 부관리자·팀원은 빨간 테두리 [팀 탈퇴] + 확인창
- 팀 해체 (D-075, D-080): 확인창에 팀 이름을 보여주고 입력칸을 둔다. 팀 이름과 똑같이(앞뒤 공백만 무시) 입력해야 [다음]이 켜진다 → "정말 삭제할까요? 되돌릴 수 없습니다." 확인창 → [삭제]로 해체. 서버도 팀 이름을 받아 다시 확인한다. 그 팀과 관련된 정보를 완전히 지운다
- 관리자를 넘기면 원래 관리자는 부관리자가 된다 (D-077)
- 관리자는 관리자를 넘긴 뒤에만 탈퇴. 혼자 남은 팀은 팀 해체가 곧 탈퇴 (D-019)
- 팀 공간의 작업·캘린더·히스토리 탭은 팀 작업 페이지 등 해당 작업에서 만든다 (D-072)
- 팀 만들기 모달은 공통 레이아웃에 둔다 (D-073)
- 상세 설계: database.md teams·team_members, api.md 6.6, TeamInfoView_screen.md, MainLayout_screen.md (팀 목록·팀 만들기 모달)
- 이전 프로젝트에서 승인된 진행 계획 (참고)
  - DB: teams(팀 정보), team_members(팀·회원·역할 owner/manager/member·합류 시각, 팀·회원 조합 UNIQUE, 팀 해체 시 함께 삭제)
  - API: 내 팀 목록, 팀 만들기, 팀 정보(내 역할 포함), 팀원 목록, 팀 정보 수정, 팀원 내보내기, 역할 변경(부관리자 지정·해제), 관리자 넘기기, 팀 탈퇴, 팀 해체. 권한·소속 확인은 서버에서, 역할을 바꾸는 처리는 트랜잭션
  - 팀에 속하지 않은 회원은 팀 정보·팀원 목록을 보거나 바꿀 수 없다 (404). 권한이 없는 요청은 서버에서 막는다
  - 테스트: 역할별 권한 표, 경계값, 남의 팀, 관리자 혼자 탈퇴, 동시 변경
  - 화면: MainLayout 갱신(팀 목록·팀 만들기·팀 공간 메뉴 탭), TeamInfoView 새로 작성

### 8.8 팀 초대/알림
- 초대와 팀 탈퇴는 팀원 누구나 가능 (D-008)
- 이메일로 회원을 지정해 초대 → 알림 생성 + 안내 메일. 초대 메일은 안내만 하고, 수락/거절은 사이트 알림에서 한다 (D-009)
- 알림 종류는 팀 초대, 작업자 지정, 마감 임박 (D-024 → D-127, D-128)
- 초대 수락으로 가입된 팀이 20개를 넘을 수 없다 (D-078)
- 팀 정보 탭 "팀원 (N명)" 오른쪽 [초대] → 모달에서 이메일 입력 (D-091)
- 가입하지 않은 이메일이면 "가입된 회원이 아닙니다." (D-092). 이미 팀원이면 막는다. 답을 기다리는 초대가 있으면 "이미 초대한 회원입니다."로 막는다 (D-093)
- 초대는 유효기간 없이 수락·거절할 때까지 남는다. 팀이 해체되면 함께 지운다 (D-094)
- 수락·거절하면 알림이 목록에서 사라진다 (D-095). 수락하면 팀원(member)으로 들어가고 그 팀이 팀 목록 맨 위에 온다 (D-089)
- 종 아이콘에 안 본 알림 개수 빨간 배지. 알림 창을 열면 모두 본 것으로 바뀐다 (D-096)
- 안내 메일: 제목 "[TODO] 팀 초대 안내", 보낸 사람 "TODO". 메일 발송에 실패해도 초대는 유지하고 화면에 알린다
- 초대 취소: 팀 정보 탭 "답을 기다리는 초대" 목록에서 초대한 회원 본인 또는 관리자·부관리자가 취소 (D-120)
- 거절한 회원은 같은 팀에서 24시간 동안 다시 초대할 수 없다 (D-121)
- 알림 종류 확장 (D-024 → D-127, D-128)
  - 작업자 지정: 다른 팀원이 나를 작업자로 넣으면 알림. 누르면 그 작업 상세로 이동, [X] 로 지운다 (D-127)
  - 마감 임박: 종료일 전날 00시 00분(한국 시간)부터 마감 전까지인 대기·진행 작업마다 한 번 (개인 작업은 소유자, 팀 작업은 작업자). 문구 ""{제목}" 작업이 11.12 18:00에 마감됩니다." (시간이 없으면 날짜만). 메일은 보내지 않는다. 예약 작업 없이 알림을 불러올 때 만든다 (D-128, D-138)
- 상세 설계: database.md notifications·team_invite_declines, api.md 6.7, TeamInfoView_screen.md (초대 모달, 답을 기다리는 초대), MainLayout_screen.md (알림 창)

### 8.9 팀 작업 페이지
- "내 작업만" 스위치: 켜면 내가 작업자인 카드만, 켜진 동안 드래그 불가, 다시 열면 꺼짐 (D-126)
- 실시간 연결이 끊기면 작업 화면 위에 "실시간 연결이 끊겼습니다. 다시 연결하는 중..." 띠 (D-123)
- 팀 공간의 할일·칸반·작업자 지정 (D-060, D-072). 작업자는 여러 명 (D-012)
- 화면은 개인 작업 화면(TaskView)을 그대로 쓰고 경로 /teams/{팀 id}/tasks 로 구분한다 (D-090). 팀원이면 역할 상관없이 할일·작업을 만들고 고치고 지울 수 있다 (D-030)
- 작업자는 칸반 작업의 상세 UI 에서만 지정한다. 할일에는 작업자가 없다. 그 팀의 지금 팀원 중에서 여러 명 (D-097)
- 작업자 변경은 수정 내역에 "작업자 변경"으로 남기고, 기록마다 그 시점 작업자를 저장한다 (D-099)
- 팀원이 팀을 탈퇴하거나 내보내지면 그 회원을 그 팀 작업의 작업자에서 빼고 작업마다 "작업자 변경" 기록을 남긴다 (D-100)
- 팀 할일·작업은 만든 회원이 아니라 팀에 속한다 (만든 회원이 나가거나 탈퇴해도 남는다). 팀을 해체하면 함께 지운다
- 상세 설계: database.md todos·tasks(team_id), task_assignees, task_log_assignees, task_logs, api.md 6.4·6.5, TaskView_screen.md

### 8.10 실시간 반영
- 작업 페이지의 생성/수정/삭제/이동을 같은 팀 접속자 화면에 실시간 반영 (Socket.IO). 개인 공간은 하지 않는다
- 범위에 새 알림(초대) 배지, 팀에서 내보내짐·팀 해체 시 그 팀 화면에서 바로 나가기를 더한다 (D-104)
- 내가 보고 있는 할일·작업을 다른 팀원이 바꾸면: 읽기 중이면 바로 새 내용, 수정 중이면 입력은 두고 "다른 팀원이 이 작업을 바꿨습니다." 안내, 저장하면 내 저장이 마지막. 지우면 오른쪽 UI 를 닫고 알린다 (D-103)
- 다른 팀원의 변경은 토스트 없이 화면만 바꾼다 (D-105)
- 서버는 무엇이 바뀌었는지만 알리고, 화면은 목록 API 를 다시 불러 그린다. 소켓은 서버 → 화면 방향만 쓰고 데이터 변경은 HTTP API 로 한다
- 상세 설계: api.md 6.8, TaskView_screen.md "실시간 반영", MainLayout_screen.md

### 8.11 캘린더
- 라이브러리 사용 (FullCalendar, D-002)
- 작업을 기간에 맞춰 가로 막대로 표시하고 상태별로 색을 다르게 한다. 칸반에 올라가지 않은 할일은 표시하지 않는다 (D-014)
- 하루짜리 작업이고 시간이 있으면 제목 앞에 시작 시각 (`09:00 주간 보고서`). 여러 날 작업은 제목만, 상세 모달에서 시간까지 (D-140)
- 히스토리로 옮긴 작업도 계속 표시한다 (D-015)
- 기간이 "미정"인 작업은 표시하지 않는다 (D-022)
- 보기 전용, 클릭 시 상세 모달, 오늘 날짜에 원 표시
- 히스토리 작업은 완료와 구분해 연한 회색 (D-106)
- 공휴일을 표시한다 (날짜 빨강 + 이름). 공공데이터포털 "한국천문연구원 특일 정보" API, 키는 사용자가 발급. 가져오지 못하면 공휴일 없이 보여준다. 일요일 빨강, 토요일 파랑 (D-107)
- 상세 모달: 상태(히스토리면 "히스토리"), 제목, 기간, 작업자(팀 공간만), 내용. 수정 내역·수정 버튼 없음 (D-108)
- 위쪽에는 년월, 이전·다음, [오늘]만. 날짜 칸을 눌러도 아무 일도 없다 (D-109)
- 월간 보기 하나만. 팀 캘린더는 실시간 반영하지 않는다 (D-104 범위 밖)
- 상세 설계: api.md 6.9, CalendarView_screen.md
- 참고자료: docs/reference/캘린더 참고.png

### 8.12 히스토리
- 완료 공간으로 옮긴 시각부터 일주일이 지나면 히스토리로 옮긴다 (D-015). 완료에서 빠졌다가 다시 완료되면 그 시각부터 센다 (D-066)
- 테이블로 표시, 클릭 시 상세 모달, 읽기 전용
- 히스토리 작업은 칸반 완료 공간에서 빠지고 수정·드래그·삭제할 수 없다. 따로 테이블로 옮기지 않고 완료 시각으로 구분한다 (D-113)
- 표 열: 제목, 기간, 완료일, 작업자(팀 공간만) (D-110). 최근에 완료한 것이 위, 한 페이지 20개 (D-111)
- 상세 모달: 캘린더 상세 모달 항목(D-108) + 완료일 + 수정 내역 목록(보기만) (D-112)
- 실시간 반영하지 않는다 (D-104 범위 밖)
- 상세 설계: database.md "히스토리", api.md 6.10, HistoryView_screen.md

### 8.13 아이디/비밀번호 찾기 (D-020)
- 이메일 인증번호로 본인을 확인한다 (인증번호 규칙은 회원가입과 같음)
- 아이디는 화면에 보여준다. 비밀번호는 새 비밀번호를 입력받아 재설정한다
- 아이디 찾기: 이메일 인증 → 아이디 전체와 가입일을 보여준다 (D-114). 가입되지 않은 이메일이면 "가입되지 않은 이메일입니다." (D-117)
- 비밀번호 찾기: 아이디 + 이메일이 같은 회원일 때만 인증번호를 보낸다 (D-115). 아니면 "아이디와 이메일이 일치하는 회원이 없습니다." (D-117)
- 비밀번호를 바꾸면 그 회원의 모든 로그인을 끊고 로그인 잠금을 푼 뒤 로그인 화면으로 보낸다. 인증 후 30분 안에 바꿔야 한다 (D-116)
- 메일 제목 "[TODO] 아이디 찾기 인증번호" / "[TODO] 비밀번호 찾기 인증번호", 모양은 회원가입 인증 메일과 같다 (D-117)
- 로그인한 회원이 찾기 화면에 오면 로그인 후 화면으로 보낸다 (D-051 과 같음)
- 상세 설계: api.md 6.2, FindIdView_screen.md, FindPasswordView_screen.md

### 8.14 회원정보 수정/탈퇴
- 화면 /profile, 공통 레이아웃 안, 메뉴 탭 숨김. 바꿀 수 있는 항목: 닉네임, 이메일, 전화번호, 비밀번호 (D-129)
- 현재 비밀번호는 비밀번호 변경과 탈퇴 때만 확인한다. 탈퇴는 비밀번호 입력 뒤 "정말 탈퇴할까요? 되돌릴 수 없습니다." 확인창 (D-130)
- 다른 팀원이 있는 팀의 관리자면 탈퇴를 막고 그 팀 이름을 보여준다. 혼자인 팀은 탈퇴할 때 해체한다 (D-131)
- 탈퇴한 회원에게 온 알림은 지우고, 보낸 초대는 그 시점 닉네임으로 남긴다. 탈퇴가 끝나면 "탈퇴가 완료되었습니다." 안내 후 로그인 화면
- 상세 설계: api.md 6.11, ProfileView_screen.md
- 아이디는 변경 불가. 이메일은 바꿀 때 다시 인증. 전화번호는 인증 없이 변경 (D-021)
- 탈퇴 (D-041): 회원 정보(아이디, 이메일, 전화번호 등)를 하드 삭제해 같은 값으로 다시 가입할 수 있게 한다. 개인 공간의 작업도 삭제한다. 팀 작업과 수정 내역은 남기고 저장해 둔 그 시점의 닉네임으로 계속 표시한다. 작업자 지정에서는 그 회원만 빠진다. 재가입한 회원과 예전 기록은 연결하지 않는다
- 공통 레이아웃의 회원 메뉴(닉네임·이메일 클릭)에 회원정보 수정 항목을 추가한다 (D-053)
- 탈퇴하면 제출한 일일보고는 작성 시점 닉네임으로 남기고, 임시저장 보고는 지운다 (D-160)

### 8.15 일일보고 (D-150~D-161)
- 목적: 매일 손으로 다시 쓰던 보고를 칸반 작업으로 자동으로 채운 초안을 "확인하고 고치는 일"로 바꾼다 (D-150)
- 위치: 팀 공간의 일일보고 탭(/teams/{팀 id}/reports). 개인 공간에는 없다. 팀원 누구나 팀원의 제출한 보고를 읽는다. 보고는 시스템 안에서만 읽는다 (D-151)
- 양식 (D-152): 팀마다 1개, 관리자·부관리자가 [양식 설정] 모달에서 고친다. 머리말 한 줄(`{날짜}` → 11/11) + 구역 1~20개. 팀을 만들면 기본 양식(통계 / 진행 / 대기 / 완료 / 기타). 양식을 바꿔도 이미 저장한 보고는 그대로, 새로 여는 보고부터 적용. 바뀐 것을 알리지 않는다
- 구역 종류 (D-153): 통계(`: 완료 N건, 진행 N건, 대기 N건`), 작업 목록(고른 상태의 이 팀 작업 중 내가 작업자인 것, `[11/10~11/24] 제목 - [진행]`), 글(리치 에디터, 양식의 기본 내용). 해당 작업이 없으면 빈 채로
- 완료 범위 (D-154): 지난 보고 이후 / 지난 특정 요일 이후 / 매달 특정 날짜 이후 / 지난 주 / 지난 달. 구역마다 양식에서 정한다
- 리치 에디터 (D-155): 굵게, 기울임, 취소선, 글자 색, 글머리·번호 목록, 들여쓰기, 표, 구분선, 링크. 그림·파일·코드 블록 없음. 서버가 허용한 태그만 남기고, 화면은 v-html 없이 그린다
- 이어받기 (D-156): 회원마다 켜기/끄기 (처음 꺼짐). 켜면 새 보고의 글 구역을 같은 팀의 내 마지막 보고로 채운다
- 쓰기 (D-157): 팀마다 하루 1개. 임시저장(나만) / 제출(팀원) / 수정 제출("수정됨 · 시각"). 빈 초안 제출 가능, 삭제·수정 내역 없음. [다시 불러오기](자동 구역 하나), [새 양식 적용](보고 전체), 저장 안 하고 나가면 확인창
- 날짜·현황 (D-158): 오늘은 한국 시간. 지난 날짜는 읽기 전용. 미제출은 매일 표시하되 합류 전 날짜는 빼고, 지난 날짜에는 지금 팀에 없는 제출자도 닉네임으로 보인다
- 실시간 (D-159): 팀원의 제출·수정 제출을 열어 둔 화면에 반영. 알림은 보내지 않는다
- 보존 (D-160): 팀 탈퇴·내보내기는 남김, 회원 탈퇴는 제출한 보고만 남김, 팀 해체는 모두 지움
- 상세 설계: database.md report_templates·daily_reports, api.md 6.12, DailyReportView_screen.md

- 알림(토스트)은 화면 위쪽 가운데 카드. 안내·성공은 초록 띠, 오류는 빨강 띠
- 서버 오류 토스트 문구: "일시적인 오류가 발생했습니다. / 잠시 후 다시 시도해 주세요."
- 사용 중 로그인 만료: 어느 회원 화면이든 API 가 401 을 돌려주면 "로그인이 만료되었습니다. 다시 로그인해 주세요." 오류 토스트 후 로그인 화면으로 (로그인 API 와 화면 이동 확인용 GET /api/sessions/me 는 제외, D-118)
- 로딩 중인 버튼은 안에 작은 스피너 + "~ 중..." 문구, 비활성
- 입력 오류: 입력칸 빨강 테두리 + 칸 아래 빨강 문구(느낌표 아이콘)
- 입력 중(포커스): 흰 배경 + 기본색 테두리 + 연한 녹색 바깥 빛, 왼쪽 아이콘 기본색
- 공통 디자인 값은 한 파일에 모아 모든 화면이 같이 쓴다 (이전 프로젝트에서는 assets/styles/theme.css)
