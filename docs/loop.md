# loop.md

이 파일은 누구라도 어떤 상황이든 변경할 수 없고 유지되어야 한다.

작업을 진행하는 순서와 종료 조건을 정의한다. 모든 작업은 아래 순서를 따른다.

---

## 1. 전체 흐름

```
설계 ⟳ → (승인) → 와이어프레임 ⟳ → (승인) → 구현 ⟳ → (승인) → 보안 체크 ⟳ → (승인) → 완료
```

- 모든 단계는 같은 방식으로 진행한다.
  1. AI가 그 단계의 결과물을 만든다.
  2. AI가 "2. 단계별 진행"의 완료 기준을 처음부터 끝까지 확인한다. 하나라도 만족하지 않으면 고치고 다시 확인한다. 모두 만족할 때까지 사용자에게 묻지 않고 스스로 반복한다.
  3. 완료 기준을 모두 만족하면 결과를 사용자에게 보여주고 승인을 요청한다.
  4. 승인되지 않으면 사용자의 수정 요청을 반영해 2번부터 다시 반복한다.
  5. 승인되면 todo.md "단계 승인"에 기록하고 다음 단계로 넘어간다.
- 승인 전에는 다음 단계의 결과물을 만들지 않는다. (예: 설계 승인 전에는 시안을 만들지 않고, 와이어프레임 승인 전에는 코드를 만들지 않는다)
- 진행 단위
  - 처음에는 프로젝트 전체(overview.md 핵심 기능 전부)를 한 번에 진행한다. 각 단계에서 모든 기능, 모든 화면을 끝낸 뒤 승인을 받는다.
  - 프로젝트가 완료된 뒤 들어오는 추가 요청은 그 기능만 같은 4단계로 진행한다.
- 뒤 단계에서 이미 승인된 앞 단계 결과물을 바꿔야 하면 (예: 구현 중 설계에 없는 API가 필요함) 멈추고 사용자에게 알린다. 승인을 받으면 앞 단계 문서와 시안을 함께 고친 뒤 이어서 진행한다.
- 각 단계를 시작할 때, 그리고 단계 안에서 진행 상황이 바뀔 때 todo.md "현재 단계"와 "진행 상황"을 갱신한다.

### 세션 시작
세션을 시작하면 todo.md "진행 중"과 사용자의 첫 메시지에 따라 아래와 같이 시작한다.

| "진행 중" | 사용자의 첫 메시지 | 행동 |
|---|---|---|
| 작업 있음 | 작업을 지정하지 않음 (예: "이어서 해") | 사용자에게 이어서 할 작업과 "현재 단계", "진행 상황"을 알리고 그 지점부터 진행한다 |
| 작업 있음 | 다른 작업을 요청함 | 진행 중인 작업을 멈추고 새 작업을 할지 사용자에게 묻는다. 새 작업을 하기로 하면 진행 중인 작업을 내용 그대로 백로그 맨 위로 옮긴다 |
| 비어 있음 | 프로젝트 기획이나 추가 기능을 요청함 | 그 내용으로 1번(설계)을 시작한다 |
| 비어 있음 | 작업을 지정하지 않음, 백로그 있음 | 백로그 맨 위 작업을 "진행 중"으로 옮기고 사용자에게 알린 뒤 "현재 단계"부터 진행한다. 새 작업이면 1번(설계)부터 시작한다 |
| 비어 있음 | 작업을 지정하지 않음, 백로그 없음 | 사용자에게 무슨 작업을 할지 묻는다 |

## 2. 단계별 진행

### 1. 설계
사용자의 기획을 문서로 정리한다. 코드와 시안은 만들지 않는다.

- 만드는 것
  - overview.md: 비어 있는 항목은 사용자에게 질문해서 채운다. 사용자 기획에 없는 기능을 넣지 않는다.
  - spec.md: 기술 스택
  - database.md: 테이블과 컬럼
  - api.md: 모든 API
  - structure.md: 만들 폴더와 파일
  - 화면마다 screen.md를 복사한 `{화면파일명}_screen.md` (화면 파일을 만들 경로에 미리 만든다)
  - 사용자가 결정한 내용은 decision.md에 기록한다.
- 완료 기준
  1. overview.md 핵심 기능마다 그 기능을 처리하는 화면, API, 테이블이 정해져 있다.
  2. overview.md "화면 목록"의 모든 화면에 `{화면파일명}_screen.md`가 있고, "화면 흐름"의 모든 이동이 각 화면 문서의 동작에 있다.
  3. 화면 문서에서 쓰는 모든 API가 api.md에 있고, API가 읽고 쓰는 모든 값이 database.md 컬럼과 타입, 길이가 맞다.
  4. 모든 API에 로그인 필요 여부와 권한(누구의 데이터인지)이 적혀 있다. (security.md 3번)
  5. 모든 입력값에 길이, 형식, 필수 여부가 적혀 있다. (security.md 4번)
  6. 문서에 `{{ }}` 자리표시가 남아 있지 않고, 문서끼리 서로 다른 내용이 없다. 용어는 overview.md "용어"와 같다.
  7. decision.md의 결정과 다른 내용이 없다.

### 2. 와이어프레임
승인된 설계로 모든 화면의 시안을 만든다. 실제 프로젝트 코드는 만들지 않는다.

- 만드는 것: 화면마다 `docs/mockups/{화면파일명}.html` (screen.md "시안 작성 규칙"을 따른다)
- 완료 기준
  1. overview.md "화면 목록"의 모든 화면에 시안이 있다.
  2. 시안마다 `{화면파일명}_screen.md`의 모든 화면 요소와 "6. 상태별 화면"의 모든 상태가 보인다.
  3. "화면 흐름"의 이동이 시안끼리 링크로 연결되어 있다.
  4. 서버 없이 브라우저로 바로 열리고, 브라우저 콘솔에 오류가 없다.
  5. 시안과 설계 문서가 다른 곳이 없다. 다르면 시안을 고친다. 설계를 바꿔야 하면 "1. 전체 흐름"의 앞 단계 변경 규칙을 따른다.
- 승인을 요청할 때 시안 파일 목록과 여는 방법을 알려준다. 승인되면 각 `{화면파일명}_screen.md` "8. 사용자 확인"에도 기록한다.

### 3. 구현
승인된 설계와 시안대로 화면과 기능을 만들고 테스트한다.

- 진행 순서
  1. overview.md 핵심 기능의 우선순위 순서로 기능을 하나씩 만든다. guide.md "읽는 시점"에 해당하는 문서를 읽고 따른다.
  2. 기능 하나를 만들 때마다 test.md 완료 체크리스트를 실행한다. 실패하면 고치고 처음부터 다시 실행한다. 실패할 때마다 todo.md "재시도 기록"을 갱신한다.
  3. 모든 기능을 만들면 test.md 완료 체크리스트를 전체 대상으로 한 번 더 실행한다.
- 완료 기준
  1. overview.md의 모든 핵심 기능이 동작한다.
  2. 모든 화면이 승인된 시안, `{화면파일명}_screen.md`와 같게 나온다.
  3. test.md 완료 체크리스트를 전체 대상으로 모두 통과했다.
- 승인을 요청할 때 test.md "결과 보고"를 하고, 사용자가 직접 확인할 실행 방법을 알려준다.

### 4. 보안 체크
security.md "11. 보안 체크"를 실행해 보안 문제를 찾고 고친다.

- 진행 순서
  1. security.md "11. 보안 체크" 항목을 위에서부터 순서대로 확인한다.
  2. 문제가 있으면 코드를 고치고, test.md 완료 체크리스트를 다시 실행해 기존 기능이 깨지지 않았는지 확인한 뒤, 보안 체크를 처음부터 다시 한다.
- 완료 기준
  1. security.md "11. 보안 체크"의 모든 항목이 통과 또는 해당 없음이다.
  2. 마지막 수정 뒤 test.md 완료 체크리스트를 모두 통과했다.
- 승인을 요청할 때 security.md "12. 보안 체크 결과 보고"를 한다.

### 완료
보안 체크가 승인되면 todo.md에서 "완료"로 옮기고 "세션 인계"를 갱신한다. 백로그에 작업이 있으면 맨 위 작업을 사용자에게 알리고 1번(설계)부터 시작한다. 백로그가 비어 있으면 사용자에게 다음 작업을 묻는다.

---

## 3. 종료 조건

| 상황 | 행동 |
|---|---|
| 4단계가 모두 승인됨 | "2. 단계별 진행"의 "완료"를 진행한다 |
| 같은 완료 기준이나 체크리스트 항목이 5번 연속 실패함 | 작업을 멈추고, 작업은 todo.md "진행 중"에 그대로 둔다. "막힌 일"에 실패 항목, 시도한 방법, 오류 내용을 기록한 뒤 사용자에게 질문한다 |
| 기획이나 완료 기준이 애매함 | CLAUDE.md 3번 규칙에 따라 사용자에게 질문한다 |
| 남은 컨텍스트가 부족함 | CLAUDE.md 2번 규칙을 따른다 |
