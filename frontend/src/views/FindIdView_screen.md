# FindIdView_screen.md

화면 설계의 기준 문서다. (docs/screen.md 를 복사해서 작성)

화면을 바꾸는 작업에서는 이 문서도 함께 갱신한다.

---

## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/frontend/src/views/FindIdView.vue
- **화면 이름**: 아이디 찾기
- **화면 목적**: 비회원이 가입한 이메일로 인증번호를 받아 본인을 확인하고 아이디를 본다 (D-020, D-114)
- **접근 URL**: /find-id
- **접근 권한**: 비회원 (로그인한 회원이 오면 로그인 후 화면 /personal/tasks 로 보낸다, D-051 과 같음)
- **시안 파일 경로**: 프로젝트/docs/mockups/find_id_view.html

### 시안 작성 규칙
- 파일명은 화면 파일명을 snake_case로 쓴다. (예: `Register.cshtml` → `register.html`)
- 프로젝트의 부트스트랩을 상대 경로로 불러와 실제 화면과 같은 스타일로 만든다. 서버 없이 파일을 바로 열어 볼 수 있어야 한다.
- 기능 없이 화면 모양과 "6. 상태별 화면"의 상태만 보여준다.
- 설계가 바뀌면 시안도 함께 고친다.

## 2. 레이아웃

회원가입 화면(SignupView_screen.md)과 같은 틀을 쓴다.

| 영역 | 위치 | 내용 |
|---|---|---|
| 배경 | 화면 전체 | 회원가입과 같음 |
| 카드 | 화면 가운데 | 왼쪽 브랜드 영역(AuthBrandPanel, 회원가입·로그인과 같은 컴포넌트) + 오른쪽 폼 영역 |
| 폼 제목 | 폼 영역 위쪽 | "아이디 찾기" + 안내 "가입할 때 쓴 이메일로 인증번호를 보내 드려요." |
| 인증 구역 | 폼 제목 아래 | 이메일(+[인증번호 발송]), 인증번호(+[확인]) |
| 결과 구역 | 인증을 마치면 인증 구역 자리에 | 아이디, 가입일, [로그인하기], [비밀번호 찾기] |
| 하단 링크 | 맨 아래 | "로그인으로 돌아가기" |
| 알림 | 화면 위쪽 가운데 | 토스트 |

### 반응형 기준
- 회원가입 화면과 같다 (992px 미만 1단, 576px 미만 여백 줄임, 버튼이 붙은 입력은 한 줄 유지)

## 3. 화면 요소

| 요소 | 종류 | 표시 내용 | 데이터 출처 | 비고 |
|---|---|---|---|---|
| 이메일 | 입력칸(email) (bi-envelope) | placeholder "example@email.com" | 사용자 입력 | maxlength 100, 회원가입 이메일과 같은 규칙 |
| 인증번호 발송 | 버튼 | 인증번호 발송 → (발송 후) 재발송 | POST /api/email-verifications (purpose = find_id) | 재발송은 1분 뒤, 그 전에는 "재발송 0:59" (D-035) |
| 인증번호 | 입력칸 (bi-key) | placeholder "인증번호 6자리" | 사용자 입력 | 발송 후에만 표시, maxlength 6, inputmode numeric |
| 남은 시간 | 알약 배지 | 4:59 | 발송 응답 expireDate | 회원가입과 같음 |
| 확인 | 버튼 | 확인 | POST /api/email-verifications/{id}/verify | |
| 결과 아이콘 | 아이콘 | bi-person-check (기본색 원) | 고정 | |
| 결과 문구 | 텍스트 | "회원님의 아이디입니다." | 고정 | |
| 아이디 | 강조 텍스트 | 아이디 전체 (D-114) | POST /api/users/find-id loginId | 가리지 않는다 |
| 가입일 | 텍스트 | 가입일 YYYY.MM.DD | createDate (브라우저 시간대) | |
| 로그인하기 | 버튼 | 로그인하기 | - | 회원가입 [가입하기] 와 같은 모양 |
| 비밀번호 찾기 | 보조 버튼 | 비밀번호 찾기 | - | 연한 기본색 |
| 로그인으로 돌아가기 | 링크 | 로그인으로 돌아가기 | - | /login |

## 4. 동작

| 요소 | 사용자 동작 | 결과 |
|---|---|---|
| 인증번호 발송 | 클릭 | 이메일 형식이 틀리면 칸 아래 오류. 맞으면 API: 404 EMAIL_NOT_REGISTERED 면 "가입되지 않은 이메일입니다." (D-117). 성공하면 인증번호 칸 표시 + 5분 카운트다운 + "인증번호를 보냈습니다. 메일을 확인해 주세요." |
| 재발송 | 클릭 (1분 뒤) | 회원가입과 같음 |
| 확인 | 클릭 | 틀림·만료·무효 문구는 회원가입과 같음. 맞으면 바로 POST /api/users/find-id → 결과 구역으로 바뀐다 |
| 이메일 | 발송 후 수정 | 인증번호 칸을 숨기고 처음부터 다시 발송 |
| 로그인하기 | 클릭 | /login 으로 이동 (아이디 칸에 찾은 아이디를 채운다, 쿼리로 넘기지 않고 화면 이동 상태로 넘긴다) |
| 비밀번호 찾기 | 클릭 | /find-password 로 이동 (아이디·이메일 칸을 채운다, 화면 이동 상태로 넘긴다) |
| 로그인으로 돌아가기 | 클릭 | /login |
| find-id | 400 EMAIL_NOT_VERIFIED (30분 지남) | "인증 시간이 지났습니다. 다시 인증해 주세요." + 인증 구역을 처음 상태로 |
| 모든 API | 500 등 | 서버 오류 토스트 (MAIL_SEND_FAILED 면 "메일을 보내지 못했습니다. 잠시 후 다시 시도해 주세요.") |

- 결과는 화면에만 있다. 새로고침하면 처음 상태로 돌아간다 (인증 기록은 한 번 쓰면 지워진다)

## 5. 데이터

### 사용 API
| 메서드 | 경로 | 용도 |
|---|---|---|
| POST | /api/email-verifications | 인증번호 발송 (purpose = find_id) |
| POST | /api/email-verifications/{id}/verify | 인증번호 확인 |
| POST | /api/users/find-id | 아이디·가입일 조회 |

### 사용 테이블
- users, email_verifications

## 6. 상태별 화면

| 상태 | 표시 내용 |
|---|---|
| 기본 | 이메일 칸 + [인증번호 발송], 인증번호 칸 숨김 |
| 가입되지 않은 이메일 | 이메일 칸 빨강 테두리 + "가입되지 않은 이메일입니다." |
| 인증번호 발송 후 | 회원가입과 같음 (인증번호 칸, 4:59 배지, "재발송 0:59") |
| 인증번호 틀림 / 만료 / 무효 | 회원가입과 같음 |
| 로딩 중 | 누른 버튼 안 스피너, 비활성 |
| 결과 | 인증 구역 대신 결과 카드: 아이콘, "회원님의 아이디입니다.", 아이디(크게), "가입일 2026.11.11", [로그인하기], [비밀번호 찾기] |
| 오류 | 서버 오류 토스트 |
