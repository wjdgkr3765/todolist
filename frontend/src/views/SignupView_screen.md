# SignupView_screen.md

화면 설계의 기준 문서다. (docs/screen.md 를 복사해서 작성)

화면을 바꾸는 작업에서는 이 문서도 함께 갱신한다.

---

## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/frontend/src/views/SignupView.vue
- **화면 이름**: 회원가입
- **화면 목적**: 비회원이 입력 항목을 채우고 이메일 인증을 마쳐 회원으로 가입한다
- **접근 URL**: /signup
- **접근 권한**: 비회원 (로그인한 회원이 오면 로그인 후 화면으로 보낸다, D-051)
- **시안 파일 경로**: 프로젝트/docs/mockups/signup_view.html

### 시안 작성 규칙
- 파일명은 화면 파일명을 snake_case로 쓴다. (예: `Register.cshtml` → `register.html`)
- 프로젝트의 부트스트랩을 상대 경로로 불러와 실제 화면과 같은 스타일로 만든다. 서버 없이 파일을 바로 열어 볼 수 있어야 한다.
- 기능 없이 화면 모양과 "6. 상태별 화면"의 상태만 보여준다.
- 설계가 바뀌면 시안도 함께 고친다.

## 2. 레이아웃

| 영역 | 위치 | 내용 |
|---|---|---|
| 배경 | 화면 전체 | 연한 녹색 배경 + 부드러운 원형 그라데이션 2개 |
| 가입 카드 | 화면 가운데 | 둥근 흰 카드 (최대 1040px), 왼쪽 브랜드 영역 + 오른쪽 폼 영역 2단 |
| 브랜드 영역 | 카드 왼쪽 (5:6 비율) | 녹색 그라데이션, 반투명 원 장식, 로고(체크 아이콘 + "TODO"), 문구 "함께 세우는 일정, 한눈에 보이는 진행", 설명 문구, 기능 3개(칸반보드, 캘린더, 실시간 협업), 미니 칸반 장식. 로그인 화면과 함께 쓰는 컴포넌트(AuthBrandPanel) |
| 폼 제목 | 폼 영역 위쪽 | "회원가입" + 안내 "몇 가지 정보만 입력하면 바로 시작할 수 있어요." |
| 계정 정보 구역 | 폼 제목 아래 | 구역 제목 "계정 정보" + 아이디, 비밀번호, 비밀번호 확인, 닉네임 |
| 본인 확인 구역 | 계정 정보 아래 | 구역 제목 "본인 확인" + 이메일(+인증번호), 전화번호 |
| 가입 버튼 | 폼 맨 아래 | [가입하기] (가로 꽉 차게, 그라데이션) |
| 하단 링크 | 가입 버튼 아래 | "이미 계정이 있으신가요? 로그인" |
| 알림 | 화면 위쪽 가운데 | 토스트 (가입 완료: 초록 띠, 오류: 빨강 띠) |

### 반응형 기준
- 992px 이상: 브랜드 영역과 폼 영역 좌우 2단
- 992px 미만: 1단, 브랜드 영역은 폼 위쪽 띠로 줄인다 (로고, 문구, 설명만, 기능 목록과 미니 칸반 숨김). 카드 최대 너비 560px
- 576px 미만: 화면 여백 16px, 카드 안쪽 여백 20px, 제목 크기 줄임
- 버튼이 붙은 입력(아이디, 이메일, 인증번호)은 모든 크기에서 입력칸과 버튼을 한 줄에 둔다 (버튼 글자 줄바꿈 금지)
- grid 열은 `minmax(0, …)` 로 지정해 375px 모바일에서 카드가 잘리지 않게 한다 (이전 프로젝트 화면 확인에서 발견)

## 3. 화면 요소

| 요소 | 종류 | 표시 내용 | 데이터 출처 | 비고 |
|---|---|---|---|---|
| 기능 소개 | 아이콘 목록 | 칸반보드(bi-kanban), 캘린더(bi-calendar3), 실시간 협업(bi-people) | 고정 문구 | 992px 미만 숨김 |
| 미니 칸반 | 장식 | 대기/진행/완료 칸과 빈 카드 모양 | 고정 | 992px 미만 숨김, 화면 읽기 프로그램에서 제외 |
| 입력칸 아이콘 | 아이콘 | 아이디 bi-person, 비밀번호 bi-lock, 비밀번호 확인 bi-shield-lock, 닉네임 bi-emoji-smile, 이메일 bi-envelope, 인증번호 bi-key, 전화번호 bi-phone | 고정 | 입력칸 안 왼쪽, 포커스 시 기본색 |
| 아이디 | 입력칸 | placeholder "영어와 숫자를 모두 포함 6~15자" | 사용자 입력 → users.login_id | maxlength 15 |
| 중복 확인 | 버튼 | 중복 확인 | GET /api/users/login-id-availability | 아이디 옆 |
| 아이디 안내 | 텍스트 | 확인 결과 / 형식 오류 | 화면 검사, API 응답 | 성공 초록, 오류 빨강 |
| 비밀번호 | 입력칸(password) | placeholder "영어, 숫자, 특수문자를 모두 포함 8~15자" | 사용자 입력 → users.password_hash (bcrypt) | maxlength 15 |
| 비밀번호 보기 | 아이콘 버튼 | bi-eye / bi-eye-slash | - | 비밀번호 칸 오른쪽 |
| 비밀번호 확인 | 입력칸(password) | placeholder "비밀번호를 한 번 더 입력" | 사용자 입력 | 서버로 보내지 않음, maxlength 15 |
| 닉네임 | 입력칸 | placeholder "한글, 영어, 숫자 1~8자" | 사용자 입력 → users.nickname | maxlength 8 |
| 이메일 | 입력칸(email) | placeholder "example@email.com" | 사용자 입력 → users.email | maxlength 100 |
| 인증번호 발송 | 버튼 | 인증번호 발송 → (발송 후) 재발송 | POST /api/email-verifications | 이메일 옆. 재발송은 1분 뒤 활성, 그 전에는 "재발송 0:59" (회색 비활성) |
| 인증번호 | 입력칸 | placeholder "인증번호 6자리" | 사용자 입력 | 발송 후에만 표시, maxlength 6, inputmode numeric, 숫자 외 입력 무시 (D-164) |
| 인증 확인 | 버튼 | 확인 | POST /api/email-verifications/{id}/verify | 인증번호 옆. 6자리를 모두 넣어야 눌린다 (D-164) |
| 남은 시간 | 알약 배지 | 4:59 형식 카운트다운 | 발송 응답 expireDate | 인증번호 칸 안 오른쪽, 빨강 글자 + 연한 빨강 배경 |
| 전화번호 | 입력칸(tel) | placeholder "숫자만 11자리 (예: 01012345678)" | 사용자 입력 → users.phone | maxlength 11, 숫자 외 입력 무시 |
| 가입하기 | 버튼 | 가입하기 | POST /api/users | 기본색 그라데이션 + 녹색 그림자, 가로 꽉 차게 |
| 로그인 링크 | 링크 | 로그인 | - | /login |

- 입력 규칙은 overview.md "8.1 회원 입력 규칙"을 따른다

## 4. 동작

| 요소 | 사용자 동작 | 결과 |
|---|---|---|
| 아이디 | 입력 | 이전 중복 확인 결과를 지운다 (다시 확인 필요) |
| 중복 확인 | 클릭 | 형식이 틀리면 형식 오류, 맞으면 API → "사용할 수 있는 아이디입니다." / "이미 사용 중인 아이디입니다." |
| 비밀번호 / 비밀번호 확인 / 닉네임 / 전화번호 | blur | 형식 검사 후 틀리면 칸 아래 오류 |
| 비밀번호 보기 | 클릭 | 보이기/숨기기 |
| 인증번호 발송 | 클릭 | 이메일 형식이 틀리면 오류. 맞으면 API: 중복이면 "이미 가입된 이메일입니다.", 아니면 인증번호 칸 표시 + 5분 카운트다운 + "인증번호를 보냈습니다. 메일을 확인해 주세요." |
| 재발송 | 클릭 (1분 뒤) | 새 인증번호 발송, 카운트다운 5분으로 다시 시작, 인증번호 칸 비움 |
| 인증 확인 | 클릭 | 맞으면 "인증되었습니다." + 이메일·인증번호 칸 잠금 + 발송 버튼 숨김. 틀리면 "인증번호가 틀렸습니다. (남은 횟수 N회)". 만료 "인증번호가 만료되었습니다. 다시 발송해 주세요." 5회 틀림 "인증번호가 무효가 되었습니다. 다시 발송해 주세요." |
| 이메일 | 인증 완료 후 수정 | 인증 완료된 이메일 칸 옆에 [변경] 버튼 → 클릭하면 인증 취소, 이메일 칸 다시 입력 가능 (D-039) |
| 가입하기 | 클릭 | 화면 검사: 형식 오류, 아이디 중복 확인 안 함, 이메일 인증 안 함이 있으면 해당 칸 오류 + 첫 오류 칸으로 이동. 통과하면 API → 성공: 모든 입력칸과 버튼 잠금(D-048) + "가입이 완료되었습니다." 안내 + 1.5초 뒤 /login 이동 (D-040). 전화번호 중복: 전화번호 칸에 "이미 가입된 전화번호입니다." (D-042) |
| 로그인 링크 | 클릭 | /login 으로 이동 |

## 5. 데이터

### 사용 API
| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | /api/users/login-id-availability | 아이디 중복 확인 |
| POST | /api/email-verifications | 이메일 인증번호 발송 (purpose = signup) |
| POST | /api/email-verifications/{id}/verify | 인증번호 확인 |
| POST | /api/users | 회원가입 |

### 사용 테이블
- users, email_verifications

## 6. 상태별 화면

| 상태 | 표시 내용 |
|---|---|
| 기본 | 빈 입력 폼, 인증번호 칸 숨김 |
| 아이디 확인됨 | 아이디 칸 초록 테두리 + 칸 안 초록 체크 + "사용할 수 있는 아이디입니다." |
| 인증번호 발송 후 | 인증번호 칸·확인 버튼 표시, 남은 시간 배지 4:59, 재발송 버튼 회색 비활성 "재발송 0:59", 안내 문구 |
| 인증번호 틀림 | 인증번호 칸 빨강 테두리 + "인증번호가 틀렸습니다. (남은 횟수 N회)" |
| 인증 만료 / 무효 | 인증번호 칸 빨강 테두리 + 안내 문구, 남은 시간 0:00, 재발송 버튼 활성 |
| 인증 완료 | 이메일 칸 회색 잠금 + 칸 안 초록 인증 배지 + [변경] 버튼 + "이메일 인증이 완료되었습니다." |
| 로딩 중 | 누른 버튼 안 작은 스피너, 비활성 (가입하기는 "가입 중...") |
| 가입 완료 | 토스트 "가입이 완료되었습니다. / 로그인 화면으로 이동합니다." (초록 띠). 모든 입력칸 회색 잠금, 모든 버튼 비활성 |
| 오류 | 서버 오류 토스트 (빨강 띠) |
