# ProfileView_screen.md

화면 설계의 기준 문서다. (docs/screen.md 를 복사해서 작성)

화면을 바꾸는 작업에서는 이 문서도 함께 갱신한다.

---

## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/frontend/src/views/ProfileView.vue
- **화면 이름**: 회원정보 수정
- **화면 목적**: 회원이 닉네임·이메일·전화번호·비밀번호를 바꾸고, 회원 탈퇴를 한다 (D-021, D-129~D-131). 아이디는 볼 수만 있다
- **접근 URL**: /profile (공통 레이아웃 안, 메뉴 탭 숨김)
- **접근 권한**: 회원 (비회원이 오면 로그인 화면으로, D-051)
- **시안 파일 경로**: 프로젝트/docs/mockups/profile_view.html

### 시안 작성 규칙
- 파일명은 화면 파일명을 snake_case로 쓴다. (예: `Register.cshtml` → `register.html`)
- 프로젝트의 부트스트랩을 상대 경로로 불러와 실제 화면과 같은 스타일로 만든다. 서버 없이 파일을 바로 열어 볼 수 있어야 한다.
- 기능 없이 화면 모양과 "6. 상태별 화면"의 상태만 보여준다.
- 설계가 바뀌면 시안도 함께 고친다.

## 2. 레이아웃

공통 레이아웃(MainLayout)의 내용 영역 안에 카드 세 개를 위에서 아래로 쌓는다. 메뉴 탭은 숨긴다.

| 영역 | 위치 | 내용 |
|---|---|---|
| 화면 제목 | 맨 위 | "회원정보 수정" |
| 내 정보 카드 | 제목 아래 | 아이디(읽기), 가입일(읽기), 닉네임, 이메일, 전화번호. 항목마다 따로 저장 |
| 비밀번호 변경 카드 | 가운데 | 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인, [비밀번호 변경] |
| 회원 탈퇴 카드 | 맨 아래 | 안내 문구 + 빨간 테두리 [회원 탈퇴] |
| 탈퇴 창 | 화면 가운데 (어두운 배경 위) | 1단계: 확인 내용 + 현재 비밀번호 / 2단계: 최종 확인 |
| 알림(토스트) | 화면 위쪽 가운데 | 안내 / 오류 |

### 반응형 기준
- 내용 최대 폭 640px, 왼쪽 정렬
- 버튼이 붙은 입력(닉네임 [저장], 이메일 [인증번호 발송], 인증번호 [확인], 전화번호 [저장])은 회원가입처럼 모든 크기에서 한 줄 유지
- 576px 미만: 카드 안쪽 여백 16px

## 4. 동작

| 요소 | 사용자 동작 | 결과 |
|---|---|---|
| 화면 열기 | 들어옴 | GET /api/users/me 로 칸을 채운다 |
| 닉네임 [저장] | 클릭 | 형식 검사 → POST /api/users/me/nickname → "닉네임을 바꿨습니다." 안내 토스트 + 좌측 하단 닉네임도 바꾼다 |
| 이메일 [인증번호 발송] | 클릭 | 형식 검사 → API: 409 EMAIL_DUPLICATED 면 "이미 가입된 이메일입니다." 나머지(재발송 1분, 5분 카운트다운, 틀림·만료·무효 문구)는 회원가입과 같음 |
| 이메일 | 발송 후 수정 | 인증번호 칸을 숨기고 처음부터 다시 발송 |
| 인증 [확인] | 클릭 | 맞으면 "인증되었습니다." + 이메일 칸 잠금 + [이메일 변경] 표시 + [변경] 버튼(인증 취소, D-039 와 같음) |
| [이메일 변경] | 클릭 | POST /api/users/me/email → "이메일을 바꿨습니다." 안내 토스트 + 좌측 하단 이메일도 바꾼다 + 이메일 영역을 처음 상태로. 400 EMAIL_NOT_VERIFIED(30분 지남) 면 "인증 시간이 지났습니다. 다시 인증해 주세요." + 처음 상태. 409 면 "이미 가입된 이메일입니다." |
| 전화번호 [저장] | 클릭 | 형식 검사 → POST /api/users/me/phone → "전화번호를 바꿨습니다." 안내 토스트. 409 PHONE_DUPLICATED 면 칸 아래 "이미 가입된 전화번호입니다." |
| [비밀번호 변경] | 클릭 | 화면 검사(현재 비밀번호 빈 값, 새 비밀번호 형식, 확인 불일치) → POST /api/users/me/password → 세 칸 비우고 "비밀번호를 바꿨습니다." 안내 토스트. 400 CURRENT_PASSWORD_MISMATCH 면 현재 비밀번호 칸 아래 "현재 비밀번호가 맞지 않습니다." 423 LOGIN_LOCKED 면 "비밀번호를 여러 번 틀려 N분 동안 확인할 수 없습니다." 오류 토스트 |
| [회원 탈퇴] | 클릭 | GET /api/users/me/withdrawal-check → blockingTeams 가 있으면 막힘 창, 없으면 탈퇴 창 1단계 (soloTeams 가 있으면 함께 해체될 팀 표시) |
| 막힘 창 팀 링크 | 클릭 | 창 닫고 그 팀 정보 탭(/teams/{팀 id}/info)으로 이동 |
| 탈퇴 창 [다음] | 클릭 | 2단계 확인창 |
| 2단계 [탈퇴] | 클릭 | POST /api/users/me/withdraw (현재 비밀번호) → 성공: 모든 창 닫기 + "탈퇴가 완료되었습니다." 안내 토스트 + /login 이동. 400 CURRENT_PASSWORD_MISMATCH 면 1단계로 돌아가 비밀번호 칸 아래 "현재 비밀번호가 맞지 않습니다." 409 TEAM_OWNER_CANNOT_WITHDRAW(그사이 팀원이 들어옴) 면 막힘 창으로 바꿔 받은 팀 목록을 보여준다. 423 은 비밀번호 변경과 같음 |
| 탈퇴 창 | [취소], [닫기], 바깥 클릭, Esc | 닫는다 (입력한 비밀번호는 버린다) |
| 모든 API | 500 등 | 서버 오류 토스트 |

## 5. 데이터

### 사용 API
| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | /api/users/me | 내 정보 |
| POST | /api/users/me/nickname | 닉네임 변경 |
| POST | /api/email-verifications | 이메일 변경 인증번호 발송 (purpose = change_email) |
| POST | /api/email-verifications/{id}/verify | 인증번호 확인 |
| POST | /api/users/me/email | 이메일 변경 |
| POST | /api/users/me/phone | 전화번호 변경 |
| POST | /api/users/me/password | 비밀번호 변경 |
| GET | /api/users/me/withdrawal-check | 탈퇴 전 확인 |
| POST | /api/users/me/withdraw | 회원 탈퇴 |

### 사용 테이블
- users, email_verifications, login_tokens, teams, team_members, todos, tasks, task_assignees, task_logs, task_log_assignees, notifications, team_invite_declines

## 6. 상태별 화면

| 상태 | 표시 내용 |
|---|---|
| 로딩 중 | 카드 자리에 작은 스피너 |
| 기본 | 지금 정보로 채운 칸, [저장]·[인증번호 발송] 비활성 (바뀐 것 없음) |
| 입력 오류 | 칸 빨강 테두리 + 칸 아래 문구 |
| 이메일 인증 중 / 인증 완료 | 회원가입과 같은 모양 + [이메일 변경] |
| 처리 중 | 누른 버튼 안 스피너 + "저장 중..." / "변경 중..." / "탈퇴 중...", 비활성 |
| 탈퇴 막힘 | 막힘 창 + 팀 목록 |
| 탈퇴 1단계 | 안내 + (혼자인 팀 목록) + 비밀번호 칸 |
| 탈퇴 2단계 | 최종 확인창 |
| 오류 | 오류 토스트 |
