# DailyReportView_screen.md

화면 설계의 기준 문서다. (docs/screen.md 를 복사해서 작성)

화면을 바꾸는 작업에서는 이 문서도 함께 갱신한다.

---

## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/frontend/src/views/DailyReportView.vue
- **화면 이름**: 일일보고
- **화면 목적**: 칸반 작업으로 자동으로 채운 오늘 보고 초안을 고쳐 임시저장·제출하고, 팀원의 제출 현황과 보고를 본다 (D-150)
- **접근 URL**: /teams/{팀 id}/reports (팀 공간만, D-151)
- **접근 권한**: 그 팀의 팀원 (역할 상관없이). [양식 설정]은 관리자·부관리자만
- **시안 파일 경로**: 프로젝트/docs/mockups/daily_report_view.html

### 시안 작성 규칙
- 파일명은 화면 파일명을 snake_case로 쓴다. (예: `Register.cshtml` → `register.html`)
- 프로젝트의 부트스트랩을 상대 경로로 불러와 실제 화면과 같은 스타일로 만든다. 서버 없이 파일을 바로 열어 볼 수 있어야 한다.
- 서버 없이 시안 안에서 "4. 동작"대로 움직이게 만든다. 버튼, 입력 검사 문구, 저장·수정·삭제, 패널·모달·확인창 열고 닫기, 드래그, 시안끼리 이동하는 링크가 실제 화면처럼 동작해야 한다. 데이터는 가짜 데이터를 쓰고 새로고침하면 처음 상태로 돌아간다.
- 드래그처럼 실제 화면에서 라이브러리를 쓰는 동작은 시안에서도 같은 라이브러리를 프로젝트에서 상대 경로로 불러와 쓴다.
- "6. 상태별 화면"의 모든 상태는 시안 위쪽 "시안 상태" 선택 막대로도 볼 수 있게 한다. 로딩 중, 서버 오류처럼 직접 만들기 어려운 상태도 여기서 고른다.
- 동작 코드가 길면 화면 파일명과 같은 이름의 JS 파일로 나눈다. (예: `task_view.html` → `task_view.js`)
- 설계가 바뀌면 시안도 함께 고친다.

## 2. 레이아웃

공통 레이아웃(MainLayout)의 내용 영역 안에 들어간다. 메뉴 탭은 팀 공간 탭(작업 / 캘린더 / 팀 정보 / 히스토리 / 일일보고)이고 일일보고가 선택된다.

| 영역 | 위치 | 내용 |
|---|---|---|
| 머리 | 내용 영역 맨 위 | 제목 "일일보고" + 날짜 이동 (‹ 2026.11.11 (수) › [오늘]) + 오른쪽 [양식 설정] (관리자·부관리자만) |
| 팀원 보고 현황 | 머리 아래 왼쪽 카드 | 팀원 목록 (내 행 맨 위) |
| 보고 영역 | 머리 아래 오른쪽 카드 | 고른 사람의 보고. 내 오늘 보고면 쓰기, 나머지는 읽기 전용 |
| 양식 설정 모달 | 화면 가운데 (어두운 배경 위) | 머리말 + 구역 목록 편집 |
| 확인창 | 화면 가운데 | [다시 불러오기], [새 양식 적용], 저장하지 않고 나가기 |
| 알림(토스트) | 화면 위쪽 가운데 | 안내·오류 토스트 |

### 반응형 기준
- 내용 영역 최소 폭 320px 을 따른다 (MainLayout_screen.md)
- 992px 이상: 왼쪽 현황 280px + 오른쪽 보고 영역 나머지
- 992px 미만 (D-161): 현황 목록만 보인다. 팀원을 누르면 보고 영역이 내용 영역 전체에 나오고 맨 위에 [‹ 목록] 버튼. 누르면 목록으로 돌아간다 (저장하지 않은 내용이 있으면 확인창)
- 576px 미만: 편집기 도구 막대는 한 줄에 다 들어가지 않으면 가로로 스크롤한다

## 4. 동작

| [제출] / [수정 제출] | 클릭 | 글 수 검사 → POST …/save (action submit) → 안내 토스트 "보고를 제출했습니다." / "보고를 수정했습니다." + 상태 "제출 완료 · 시각" (수정이면 "수정됨 · 시각") + 내 행 배지 제출 완료 + [임시저장] 숨김. 빈 초안도 제출된다 (D-157) |

| 저장 | 409 REPORT_ALREADY_SUBMITTED | (다른 탭에서 제출한 경우) 오류 토스트 "이미 제출한 보고입니다. [수정 제출]로 저장해 주세요." + 버튼을 [수정 제출]로 바꾼다 (쓰던 내용은 둔다) |

| 저장하지 않고 나가기 | 다른 행·날짜·탭·팀으로 옮김, [‹ 목록] | 확인창 "저장하지 않은 내용이 있습니다. 나갈까요?" [머무르기] [나가기] (D-157). 창 닫기·새로고침은 브라우저 기본 확인창 (beforeunload) |
| [양식 설정] | 클릭 | GET /api/teams/{id}/report-template → 모달 열기 |
| 모달 구역 종류 | 바꿈 | 그 종류의 설정 칸으로 바꾼다 (작업 목록이면 진행 체크, 완료 범위 지난 보고 이후 기본) |
| 모달 [+ 구역 추가] | 클릭 | 맨 아래 글 구역 "새 구역" 추가, 제목 칸에 포커스 |
| 모달 구역 | 끌어다 놓기 | 놓은 자리로 순서 바꾸기 (SortableJS, 5px 이상 움직여야 드래그) |
| 모달 [삭제] | 클릭 | 그 구역 빼기 (확인창 없음, [저장] 전까지 되돌릴 수 있게 [취소]가 있다) |
| 모달 [저장] | 클릭 | 화면 검사(구역 제목 빈 값 "구역 제목을 입력해 주세요.", 30자 초과, 같은 제목 "구역 제목이 겹칩니다.", 작업 목록 상태 0개 "상태를 하나 이상 골라 주세요.", 기본 내용 5,000자 초과. 해당 칸 아래 빨강 문구, 첫 오류 칸으로 이동) → POST /api/teams/{id}/report-template/update → 모달 닫기 + 안내 토스트 "양식을 저장했습니다. 새로 여는 보고부터 적용됩니다." 지금 쓰던 보고는 바꾸지 않는다 |
| 모달 저장 | 403 | 모달 닫기 + "권한이 없습니다." 오류 토스트 + [양식 설정] 버튼 숨김 (그사이 역할이 바뀜) |
| 모달 [취소], 바깥 클릭, Esc | 클릭 | 고친 것을 버리고 닫는다 |
| 링크 (읽기 전용 보고) | 클릭 | 새 탭으로 연다 |
| 모든 API | 500 등 | 서버 오류 토스트 |

### 실시간 반영 (D-159)
| 받은 이벤트 | 화면 상태 | 결과 |
|---|---|---|
| team:reports-changed | 보고 있는 날짜와 reportDate 가 같음 | 현황 목록을 다시 불러온다 (고른 행은 그대로) |
| team:reports-changed | 그 사람 보고를 읽기 전용으로 보고 있음 | 그 보고를 다시 불러와 바로 바꾼다 |
| team:reports-changed | 내 보고를 쓰는 중 (내가 다른 탭에서 제출한 경우 포함) | 목록만 바꾸고 쓰던 내용은 건드리지 않는다 |
| teams:changed (removed / dissolved) | 이 팀 공간을 보고 있음 | MainLayout 이 처리 (/personal/tasks 로 이동). 저장하지 않은 내용 확인창은 띄우지 않는다 |
| 다시 연결됨 | 언제나 | 현황 목록을 다시 불러온다. 읽고 있는 남의 보고도 다시 불러온다 |

- 양식이 바뀐 것은 알리지 않는다 (D-152)

| 자동 구역이 빔 | 해당 작업이 없어 빈 구역 (흐린 자리표시) |

| 저장 중 | 누른 버튼에 스피너 + "저장 중..." / "제출 중...", 버튼 비활성 |
| 남의 보고 읽기 | 읽기 전용 (도구 막대·버튼·스위치 없음), "제출 완료 · 시각" |
