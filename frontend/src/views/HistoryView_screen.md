# HistoryView_screen.md

화면 설계의 기준 문서다. (docs/screen.md 를 복사해서 작성)

화면을 바꾸는 작업에서는 이 문서도 함께 갱신한다.

---

## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/frontend/src/views/HistoryView.vue
- **화면 이름**: 히스토리
- **화면 목적**: 완료한 지 일주일이 지난 작업을 표로 보고, 눌러서 상세 내용과 수정 내역을 본다 (읽기 전용, D-015, D-113)
- **접근 URL**: /personal/history (개인 공간), /teams/{팀 id}/history (팀 공간, D-090). 같은 화면 파일을 쓰고 경로로 공간을 구분한다
- **접근 권한**: 회원 (개인 공간), 그 팀의 팀원 (팀 공간, 역할 상관없이)
- **시안 파일 경로**: 프로젝트/docs/mockups/history_view.html

### 시안 작성 규칙
- 파일명은 화면 파일명을 snake_case로 쓴다. (예: `Register.cshtml` → `register.html`)
- 프로젝트의 부트스트랩을 상대 경로로 불러와 실제 화면과 같은 스타일로 만든다. 서버 없이 파일을 바로 열어 볼 수 있어야 한다.
- 기능 없이 화면 모양과 "6. 상태별 화면"의 상태만 보여준다.
- 설계가 바뀌면 시안도 함께 고친다.

## 2. 레이아웃

공통 레이아웃(MainLayout)의 내용 영역 안에 카드 하나로 들어간다.

| 영역 | 위치 | 내용 |
|---|---|---|
| 머리 | 카드 맨 위 | 제목 "히스토리 (N개)" + 아래 안내 "완료한 지 7일이 지난 작업입니다." |
| 히스토리 표 | 가운데 | 제목 / 기간 / 완료일 / 작업자(팀 공간만) (D-110) |
| 페이지 번호 | 표 아래 가운데 | [‹] 1 2 3 4 5 [›] (D-111) |
| 상세 모달 | 화면 가운데 (어두운 배경 위) | 누른 작업의 상세 + 수정 내역 (D-112) |
| 알림(토스트) | 화면 위쪽 가운데 | 오류 토스트 |

### 반응형 기준
- 내용 영역 최소 폭 320px 을 따른다 (MainLayout_screen.md)
- 768px 미만: 기간·작업자 열을 숨기고 제목 아래에 작은 글씨로 "기간 · 작업자"를 보여준다 (기간은 표와 같이 `~ 종료일`, D-143). 완료일 열은 남긴다

## 3. 화면 요소

| 요소 | 종류 | 표시 내용 | 데이터 출처 | 비고 |
|---|---|---|---|---|
| 제목 | 텍스트 | 히스토리 (N개) | totalCount | |
| 안내 | 텍스트 | 완료한 지 7일이 지난 작업입니다. | 고정 | |
| 표 머리 | 표 머리 | 제목 / 기간 / 완료일 / 작업자 | 고정 | 작업자 열은 팀 공간만 |
| 히스토리 행 | 표 행 | 제목(넘치면 …) / 기간(종료일만, 시간 없이 `~ 2026.10.27`, D-143. 미정이면 "미정" 배지) / 완료일 YYYY.MM.DD (브라우저 시간대) / 작업자(1명: 닉네임, 2명 이상: "첫 닉네임 외 N명", 없으면 흐린 "없음", D-098 과 같은 방식) | GET /api/.../history | 최근에 완료한 것이 위 (D-111) |
| 빈 목록 | 텍스트 | bi-clock-history + "히스토리가 없습니다." + "완료한 지 7일이 지난 작업이 여기에 모입니다." | - | |
| 페이지 번호 | 버튼 묶음 | [‹] 현재 페이지 주변 최대 5개 번호 [›] | totalCount, page | 1페이지뿐이면 숨김. 첫 페이지면 [‹], 마지막이면 [›] 비활성 |
| 상세 모달 | 모달 (D-108, D-112) | 상태 배지 "히스토리", 제목, 기간(시작~종료 전체, 시간 포함, D-139), 완료일(YYYY.MM.DD HH:mm), 작업자(팀 공간만, 지정한 순 쉼표로, 없으면 "없음"), 내용(줄바꿈 그대로), 수정 내역 목록, [닫기] | 누른 HistoryTask + GET /api/tasks/{id}/logs | 보기 전용. 수정·삭제 버튼 없음 |
| 수정 내역 목록 | 목록 (보기만) | TaskView 수정 내역 줄과 같은 모양 (1줄: 종류 문구 / 2줄: 시각 · 닉네임), 최근 것이 위 | TaskLog | 줄을 눌러도 아무 일도 없다 (모달 안에 모달을 띄우지 않는다). 오른쪽 화살표 없음 |

## 4. 동작

| 요소 | 사용자 동작 | 결과 |
|---|---|---|
| 화면 열기 | 들어옴 | 1페이지를 불러온다. 팀 공간에서 404 면 MainLayout 과 같은 처리 (팀 목록 새로고침 + /personal/tasks) |
| 페이지 번호 / [‹] [›] | 클릭 | 그 페이지를 불러오고 표 맨 위로 스크롤. 빈 배열이 오면(그사이 줄어듦) 마지막 페이지를 다시 불러온다 |
| 히스토리 행 | 클릭 | 상세 모달 열기 + 수정 내역 불러오기 |
| 상세 모달 | [닫기], X, 바깥 클릭, Esc | 닫는다 |
| 수정 내역 | 404 (그사이 팀 해체 등) | 모달 닫기 + 오류 토스트 "작업을 찾을 수 없습니다." + 목록 다시 불러오기 |
| 목록 API | 실패 (500 등) | 서버 오류 토스트 |

- 히스토리는 실시간 반영 대상이 아니다 (D-104). 페이지를 바꾸거나 화면을 다시 열면 새로 불러온다

### 사용 API

|---|---|---|
| GET | /api/personal/history?page= | 개인 공간 히스토리 |

- tasks, task_assignees, task_logs, task_log_assignees, users, team_members

## 6. 상태별 화면

| 상태 | 표시 내용 |
|---|---|
| 로딩 중 | 표 자리에 작은 스피너 + "불러오는 중..." |
| 데이터 없음 | 빈 목록 안내, 페이지 번호 숨김 |
| 기본 | 표 + 페이지 번호 (2페이지 이상일 때) |
| 팀 공간 | 작업자 열 있음 |
| 개인 공간 | 작업자 열 없음 |
| 좁은 화면 | 제목 아래 작은 글씨로 기간 · 작업자 |
| 상세 모달 | 어두운 배경 + 가운데 모달, 수정 내역 로딩 중이면 그 자리에 작은 스피너 |
| 오류 | 서버 오류 토스트 |
